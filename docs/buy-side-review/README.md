# 三种买方视角的产品评审与执行

本轮是模拟买方角色的代理试用，不代表真人用户访谈或专业投资认证。

本地基线：`d9a86d1`，标签 `v0.3.0`；改进分支：`improve/buy-side-review`。源码、测试和文档已存入本地 Git，运行数据库、密钥、依赖目录及临时研究导出不进入 Git。开始评审时另外做了 SQLite 本机备份。

本轮完成版本为 **v0.3.1**。集成结果、真实对话重放和未解决的问题见 [最终验收](acceptance.md)。

| 视角 | 性格与研究取向 | 审美与使用偏好 | 评审记录 |
|---|---|---|---|
| 价值研究员 | 审慎、怀疑、重风险与证据 | 报纸式清晰排版、可追溯底稿 | [价值评审](value-review.md) |
| 成长研究员 | 好奇、探索、追问商业化 | 有活力但克制、方便迭代问题 | [成长评审](growth-review.md) |
| 组合基金经理 | 果断、时间紧、关注决策效率 | 极简、高对比、重点先呈现 | [基金经理评审](pm-review.md) |

每份评审区分可复现缺陷、研究能力边界和主观审美偏好，保留实际步骤与证据。三位对应的执行代理必须先复核建议，再实施被证据支持且范围明确的改进；不同审美意见不能直接导致全站反复换皮。

评审测试使用独立副本或只读方式，原华宇研究、原始对话及既有估值不作为可随意修改的测试对象。真实模型调用是测试，不用于声称投资建议正确。最终由主代理集成、运行回归检查、验证页面并单独提交改进版本。

## 一对一复核分工

| 评审 | 独立执行代理 | 执行记录与边界 |
|---|---|---|
| review_value | execute_value | [价值复核与执行](value-execution.md)：估值与报告关联、财务核验；只读执行问题交成长执行者统一修复 |
| review_growth | execute_growth | [成长复核与执行](growth-execution.md)：最新用户约束、正文阅读完成条件、真实覆盖和来源列表 |
| research_audit（本轮 PM 角色） | execute_pm | [PM 复核与执行](pm-execution.md)：当前报告导出、可携带证据包、目录与来源文案 |

运行环境最多同时容纳主代理加三个子代理，因此两轮分批执行。三位评审中，价值与成长完成浏览器操作及各一轮真实对话；PM 的独立浏览器不可达，完成了只读 API 验证和源码复核，未冒称视觉验收。主代理负责补做最终浏览器检查。

## 本轮决策

| 发现 | 优先级 | 处理原则 |
|---|---|---|
| 不联网、不改报告仍被强制生成报告 | P1 | 修正跨分句误判，在工具执行前落实最新用户约束 |
| 要求打开正文，但只搜索摘要就声称查证完成 | P1 | 依据真实执行记录检查正文读取，补读有界，无法完成时显示缺口 |
| 网络来源只显示最后8条且无总数 | P2 | 合并摘要/正文/失败状态，显示总数并可展开全部 |
| 新估值未纳入旧报告却没有提示 | P2 | 明确关联到具体情景，显示差异；不自动改旧稿 |
| 负基期空同比显示绿色“未计算” | P2 | 使用已有金额变化，不能计算时明确原因并使用中性色 |
| 当前稿导出混入大量历史JSON | P1 | 当前阅读稿与完整审计材料分开，历史全部保留 |
| ZIP内引用仍指向本机服务 | P1 | 已打包PDF用相对路径，外部原文明确需要联网 |
| 半年报被统一标年报，目录位置较晚 | P2 | 修正类型标签、前置目录、按需查看证据 |
| 章节级版本差异比较 | P2 | 本轮暂缓；先保持现有完整旧稿与修订说明，另做独立交互设计 |
| 再次全面换配色/增加大量研究卡片 | 偏好 | 不采用；保留现有主题，优先可读性、控制感与证据定位 |
