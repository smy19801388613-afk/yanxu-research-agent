## 实际操作与观察

### 1. 从“讨论研究思路”开始探索

步骤：选择独立研究及其空白对话 → 点击“讨论研究思路” → 检查输入框。

观察：按钮仅填入“我更关心利润增长的可持续性……有哪些反证和缺失资料”。没有自动发出请求，这一点好；但快捷问题不随既有报告中的 AI 商业化、客户付费、竞争缺口变化。“深入研究并保存报告”在空态和右栏都有醒目入口，局部探索的路径较弱。

影响：已有研究越丰富，用户越需要自己重新描述具体未解决问题；容易直接走整篇报告更新。

严重性：P2，可用性。建议从既有 memo.open_questions / research_plan 或 gaps 提供最多 3 张有上下文的研究卡片，点击只预填当前问题，并显示“会检索资料 / 不自动更新报告”。不是只换三句固定提示词。

证据：浏览器实际填入上述问题；代码核对 web/src/AgentChat.tsx:65 的固定入口。

### 2. 一轮真实联网查证：完成提示超过实际覆盖

步骤：将输入替换为“评审·成长｜请只做一次聚焦查证……围绕华宇万象和法律 MCP，找付费客户/订单/收入、一个具体竞争替代方案、一条反证和三个追问；优先官网/公告，打开关键正文；不保存报告、不计算估值，最多两组搜索” → 发送 → 展开研究过程。

观察：本轮只有 1 次 web_search（4 个查询、18 个结果），没有 read_webpage / read_public_pdf / PDF 页读取动作；模型以“已完成一轮聚焦查证”开头答复。搜索主要返回公司财报、监管、会议及持仓新闻，没有取得一个具体竞品产品或法律 MCP 付费正文。答复把 Kimi 的一般法律问答能力作为替代，称合作“非排他绑定”，本轮没有相应证据；将整体经营现金流压力联系到 AI 订单回款时，也没有 AI 分项资料。

正面：真实执行了搜索，能明确区分公司宣传和收入，并识别汽车软件合同并非万象订单；按要求及时停止，没有擅自更新报告或估值。副本自带既有全文来源，因而不能把所有财务内容都称为本轮凭空生成。

影响：用户需要自己打开工具过程，才能发现“优先官方并打开正文”的关键部分未完成。完成答复中没有明显的覆盖缺口状态；竞争问题尚未回答却看起来已经完成。

严重性：P1，研究可靠性 / 完成状态缺陷。建议执行完成后由程序从真实 steps 计算“搜索 N / 本轮正文 N / 复用材料 N / 尚未完成项”，正文未读取明确显示“本轮仅检索摘要”；把本轮新增证据与复用旧证据分开显示。对要求正文查证且只有摘要的情况返回部分完成，不用提示词代替完成条件。不要为了凑数量自动增加无限调用。

证据：[本轮原始记录](growth-conversation.json)、[计数证明](growth-proof.json)、[浏览器最终可访问文本](growth-final-ax.txt)、[研究过程截图](growth-process.png)。turn `1b4438b96fc0`，2026-10-02 14:41 UTC 发出、14:42 UTC 答复。

### 3. 检查“网络来源”：有日期和摘要标签，但漏掉重要来源

步骤：完成联网后检查右栏网络来源及答复末尾引用 → 展开研究过程。

观察：右栏只有最后 8 条搜索结果，显示董事会、担保、监管等，未见本轮排在前面的官网与主要半年报报道。每条明确标“搜索摘要”，很有价值；但缺少“共 18 条”或“查看全部”，也不汇合正文阅读状态。答复正文已有引用和日期，末尾另追加一批不直接支持主要观点的搜索摘要（股东会、百科、机构持仓等），阅读负担较大。

影响：用户很难判断来源栏是全部材料、关键证据，还是最后几条结果；“相关性较弱的八条”占据有限侧栏，比仅仅颜色或字号更影响信任。

严重性：P2，来源可读性与覆盖呈现缺陷。建议按规范 URL 去重合并搜索和正文，优先显示已读且被引用的关键来源，显示总数与展开全部；状态统一为摘要 / 已读正文 / 读取失败，保留日期未知标记。引用短标签用“官网·产品 / 公告·半年报 / 媒体·日期”，完整标题放展开层；不要把搜索结果数当作证据强度。

证据：growth-final-ax.txt 中网络来源仅 8 条；growth-conversation.json 内 18 条。代码核对 web/src/AgentChat.tsx:62：收集 web_search 后直接 `.slice(-8)`，未合入 read_webpage。

### 4. 公司报告和历史迭代

步骤：点击“公司研究 6 项事实 · 第 7 版” → 点击目录“竞争与行业位置” → 点击“研究版本” → 展开“第 6 版 → 第 7 版”。

观察：章节目录可定位；章节“证据待补充”、论点的反证与何时改变判断都清楚。报告首屏先占据三张财务卡，产品/竞争探索在较长正文之后。多个链接标题仅“北京华宇软件股份有限公司 · 第 N 页”，不读 URL 难以判断是年报、半年报还是更正材料。历史展开的是第 6 版全文，有修订说明、保留旧稿；没有本轮改动的章节级对照。当前报告只有“深入研究并更新”明显操作，尚未解决的具体问题不能就地继续问。

影响：从某项判断出发建立下一步研究较费力；核验修订需要重复阅读整篇旧稿。

严重性：P2，迭代可用性。建议在报告章节/核实问题旁加“继续查证”动作，跳到当前聊天并填入该问题、章节、来源与版本；历史显示变更章节列表及前后文本对照，默认折叠全文。这不要求新模型、不改报告内容。

证据：[报告首屏](growth-report.png)、[竞争章节](growth-competition.png)、[历史版本展开](growth-versions.png)。文件边界：web/src/MemoView.tsx、App.tsx。

## 审美偏好（不当成功能缺陷）

紫色主色、淡灰侧栏和清楚的卡片留白整体克制，适合研究。我的个人偏好是把“待证实 / 反证 / 下一步”用更活跃但少量的色标与短卡片呈现，减少长段落之间同等权重的感受。没有必要重做品牌或增加装饰图表。负利润“未计算”用绿色容易被误读成正向结果，可改中性色；这里不主张把负数同比强行算出来。

## 建议本轮实现的 4 个有界改进

1. **P1，真实覆盖状态**：AgentChat 中显示由实际工具步骤计算的完成摘要；仅搜索摘要时显示部分完成及未读状态。涉及 web/src/AgentChat.tsx，必要时 app/agent.py 只增加结构化完成元数据。验收：本轮记录回放应明确显示搜索 1、结果 18、新增正文阅读 0，不再只能看到“完成”。
2. **P2，网络来源整理**：去重汇合搜索/正文/失败状态、来源总数、查看全部与相关引用优先；上限只控制默认折叠数量。涉及 AgentChat.tsx、现有 WebReferences 组件。验收：18 条均可访问，已读正文不被摘要状态覆盖。
3. **P2，可继续的研究问题**：从已有报告核实清单提取最多 3 个入口，章节内“继续查证”带上下文预填，不自动发送和不自动改报告。涉及 MemoView.tsx、AgentChat.tsx、App.tsx。
4. **P2，报告变化摘要**：第 6→7 版显示哪些章节文本改变，展开显示前后文本；保留完整旧版。涉及 App.tsx / 独立小组件、样式文件；用现有 memo 数据即可，不增模型调用。

以上是建议边界，本评审未修改产品代码、未提交代码、未重启服务或部署，也未触碰密钥。
