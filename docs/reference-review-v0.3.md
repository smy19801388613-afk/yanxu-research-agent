## 建议的数据结构与写作顺序

1. **Evidence**：稳定 ID、来源类型、标题、原始 URL/PDF 页码、发布日期、抓取日期、正文/引文、提取方式、事实状态。搜索摘要只作线索；正文才可支撑主要论断。同一转载链不计作多个独立验证。
2. **Claim**：结论、事实/推断/假设类型、支持证据 ID、相反证据 ID、缺口、使结论失效的可观察条件。未找到反证不同于不存在反证。
3. **Business**：具体产品、客户/付费方、解决的问题、交付模式、收费方式、收入归属、竞争替代方案。像“万象大模型4.0”应明确区分产品发布、客户使用与可归属收入。
4. **Valuation**：方法选择理由、可比公司筛选理由、历史或预测口径、假设来源、用户采用状态、程序计算结果。缺少当前价格和对应日期，不声称潜在涨幅或安全边际。
5. **Catalyst**：实际事件、预计时间或未知、兑现机制、影响哪项经营/估值假设、来源、核验动作。不能将笼统“AI发展”当作已确定的催化剂。
6. **Memo**：先给研究结论与核心分歧，再展开业务及竞争、财务驱动、支持/反对论点、估值情景、催化剂和验证清单。允许“证据尚不足以定价”，但必须说明最关键的缺口与可执行查证路径。

每轮研究先确定问题和披露截止日，然后从公司公告/产品、行业及竞争、近期事件、负面或矛盾证据四个角度检索，阅读相关正文，再提出新追问。停止条件应取决于关键问题覆盖与证据增量，而不是机械凑来源数量。

## 集成代码审阅交接

下列为集成过程中的审阅发现，已反馈主开发者；此处记录发现时状态，不代表最终版本仍存在。没有修改 `agent.py`、`deep_research.py`、`research.py`。

- `research.execute` 进入深度研究前保留旧 run 对象，而深度研究增量保存来源与附件。取消/意外异常后若用旧对象执行 finally 保存，会覆盖增量状态。需重新加载快照后设置终止状态。
- `deep_research.build` 应判断已接入的是匹配年度的全文年报，不能以任意文件存在作为跳过获取年报的条件。无对话自动研究路径也应登记附件元数据、刷新年报可用性。
- 来源上下文原先按最多 65 条、每条 6500 字符截取，没有总长度约束；草稿、审阅、修订重复发送可能超出服务预算。应按相关性、来源类型、正文可用性选择，并增加总字符预算；允许引用 ID 应与实际提供的材料保持一致。
- `validate_memo` 的 `theses` / `sections` 内若出现非对象，分别可触发 AttributeError / TypeError，而构建流程仅捕获 ValueError 进入一次校验修订。已用内存测试复现，应统一结构错误反馈，确保模型能根据反馈修复。
- 网页并行读取之间应检查停止标记；单页失败不应丢失其他已完成来源。运行预算按工具边界检查，仍需保留每次网络请求自身的超时。

研究语义仍需审阅，尤其是“出处存在”与“出处支持该结论”不同。程序引用检查可证明来源曾被取得，不能代替对宣传、市场预期、因果及数值口径的判断。
